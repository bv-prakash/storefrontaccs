Custom product reviews on PDP and PLP (Mesh REST API)

Purpose

Shoppers see star ratings and review counts on PLP and PDP, open a Reviews tab on the product page, read paginated reviews, and submit new reviews (name, title, rating, body). Data is loaded and saved through an Adobe I/O Runtime / App Builder REST API (get-ratings, create-review), not through Commerce storefront GraphQL. The API base URL is set in config.json per store view; review content and moderation live in your Mesh/backend service.

Repo: https://github.com/bv-prakash/storefrontaccs/

Who does what

Merchants / backend (Mesh / App Builder)

  • Deploy and maintain the product-reviews web actions (get-ratings, create-review).
  • Expose a stable base URL (e.g. https://…/api/v1/web/product-reviews).
  • Allow CORS for storefront origins: local dev (localhost:3000), feature preview (*.aem.page), and live (*.aem.live).
  • Ensure responses include averageRating, reviewCount, reviews[], and pagination.
  • Operate review moderation in your backend if required before reviews appear in get-ratings.

Authors (da.live / AEM)

  • Use the standard Product Details block on PDP pages (reviews are built into that block, not a separate CMS block).
  • Ensure the PDP includes the Reviews tab and product-details layout from this project.
  • PLP / category pages use the Product List Page block; review stars appear under the product title when the API returns reviews for that SKU.
  • No extra block rows or cells are required—UI is rendered at runtime from the API.

Shoppers

  • PDP (under price): If reviews exist, gold stars and “N Reviews” (opens Reviews tab). If none, Be the first reviewer opens the write-review form.
  • PDP (Reviews tab): Rating summary and breakdown, Write a Review (toggles the form), review list (5 per page with Previous/Next when more than 5).
  • Write a review: Select stars, enter name, review title, and review text, then submit.
  • PLP: Stars and review count under the product name when that SKU has reviews.

Developers / implementers

  • What was built: scripts/product-reviews.js (REST client) + scripts/components/product-reviews/ (UI/CSS), wired in scripts/commerce.js, blocks/product-details/product-details.js, and blocks/product-list-page/product-list-page.js.
  • Initialization: initializeCommerce() → initProductReviewsApi().
  • Install, file lists, remove steps: see repo scripts/components/product-reviews/README.md.

If you do not need product reviews

  • UI only: Remove PLP/PDP wiring and delete scripts/components/product-reviews/ (see Remove — UI only below).
  • Full removal: Also remove scripts/product-reviews.js, commerce.js init, and config keys (see Remove — full module below).

Remove — full module

Complete UI steps above, then remove initProductReviewsApi from scripts/commerce.js, delete scripts/product-reviews.js, remove product-reviews-api-base from config files, run npm run lint.

Local validation

  1. Set product-reviews-api-base in config.json.
  2. Start dev server (npx @adobe/aem-cli up).
  3. Test PDP (teaser, Reviews tab, form, pagination) and PLP.
  4. Run npm run lint before commit.
